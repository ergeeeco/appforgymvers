# Железный круг: Android-приложение на Python (Kivy)

Использует тот же Supabase, что и веб-версия. Файлы: main.py (приложение), buildozer.spec (сборка APK), schema_v2.sql (обновление базы), icon-512.png.

## 1. База
Если вы уже выполняли schema.sql из веб-версии, выполните в SQL Editor файл schema_v2.sql. Он добавляет поля профиля, раздел «Актуальная форма», проверки значений и защиту от спама. Если базы ещё нет, сначала выполните schema.sql из папки iron-circle, затем schema_v2.sql.

## 2. Настройка
В начале main.py впишите Project URL и anon public key (Supabase → Project Settings → API). Ключ service_role в приложение вставлять нельзя.

## 3. Проверка на компьютере
pip install kivy requests certifi pillow plyer
python main.py

## 4. Сборка APK (Linux или Windows через WSL, Ubuntu)
sudo apt install -y git zip unzip openjdk-17-jdk python3-pip autoconf libtool pkg-config zlib1g-dev libncurses5-dev libffi-dev libssl-dev
pip install buildozer cython
buildozer -v android debug
Готовый APK появится в папке bin. Первая сборка занимает 30 минут и больше. Если сборка падает на ffpyplayer, удалите его из requirements в buildozer.spec: видео тогда будут открываться во внешнем проигрывателе, а не в самом приложении.

## 5. Безопасность: что реально защищает
Код приложения на телефоне нельзя скрыть: APK распаковывается и читается за минуты, а любая обфускация (например, PyArmor) только замедляет разбор. Поэтому защита построена на сервере, и взломщик, даже получив весь код, ничего не добьётся:
- Row Level Security: каждый пользователь может менять и удалять только свои данные (профиль, посты, подписки, форму, файлы).
- Проверки значений в базе (schema_v2.sql): диапазоны весов, длины текстов, типы медиа. Подменённый клиент не запишет некорректные данные.
- Хранилище: только jpeg, mp4, mov, до 20 МБ, загрузка только в папку своего user id.
- Лимит 30 публикаций в час на пользователя.
- В приложении лежит только публичный anon key. Секретные ключи в клиенте не хранятся. Токен входа лежит в закрытой папке приложения.
- Пользовательский текст экранируется перед выводом, чтобы разметка не ломала интерфейс.

Что включить в панели Supabase:
1. Authentication → Rate limits: ограничьте число регистраций и входов с одного адреса.
2. Authentication → Attack Protection: включите CAPTCHA (hCaptcha или Cloudflare Turnstile). Для её работы в приложение придётся добавить проверку токена капчи.
3. Authentication → Providers → Email: оставьте подтверждение email включённым и поднимите минимальную длину пароля до 8.
4. Для публикации в Google Play подписывайте релиз своим ключом и храните его в безопасном месте. Play Integrity API можно подключить позже.

## Что не проверено
Я не запускал и не собирал приложение. Возможны правки при первой сборке. Особенно проверьте: выбор файлов на Android 10 и новее (при проблемах замените plyer на библиотеку androidstorage4kivy), видео внутри приложения и размер видео (лимит 20 МБ задаёт «короткий» ролик, длительность не измеряется).

## Обновление: ключи, галерея, подписчики
- Ключи Supabase теперь можно хранить в отдельном файле config.py рядом с main.py (образец: config.example.py): две строки URL = "..." и KEY = "...". Файл в .gitignore и в репозиторий не попадёт, а при замене main.py ваши ключи не пропадут.
- Фото и видео выбираются из системной галереи (кнопки «Фото из галереи» и «Видео из галереи»). Для этого в buildozer.spec добавлена библиотека androidstorage4kivy, разрешения на чтение файлов приложению больше не нужны (остался только INTERNET). Если сборка или выбор файла сломаются, сверьтесь с README этой библиотеки (нужна androidx, она включена строкой android.enable_androidx).
- Видео без ffpyplayer открываются во внешнем проигрывателе телефона.
- Списки подписчиков и подписок открываются нажатием на карточки в профиле.
